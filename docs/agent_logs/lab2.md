## Эпизод 1. Интеграция алгоритма kNN в текстовый интерфейс

### Запрос

> Дополнить текстовый интерфейс из лабораторной работы 1 функциональностью,
> необходимой для лабораторной работы 2, и записать результат в журнал.

### Результат

В меню `Lab1/src/tui.cpp` добавлен пункт `Train kNN and predict test data`.
Пункт выполняет следующие действия:

1. использует значения `k`, метрики расстояния и взвешивания, заданные
   аргументами командной строки;
2. делит загруженный датасет в соответствии с долей обучающей выборки;
3. повторно использует рассчитанные статистики предобработки для обеих частей;
4. строит матрицы признаков и кодирует отклик `Class/ASD`;
5. создаёт `KnnClassifier` или `KnnRegressor` через `IModel`;
6. случайно выбирает до пяти тестовых объектов и выводит их предсказания и
   настоящие ответы.

Существующие пункты лабораторной работы 1 для вывода сводки, статистики и
сохранения бинарного датасета сохранены.

### Изменения

- Добавлено извлечение числового или категориального отклика через
  `Dataset::get_target()`.
- Добавлено детерминированное кодирование категорий, общее для обучающей и
  тестовой выборок.
- Интерактивный ввод параметров kNN заменён обработкой аргументов запуска:
  `--k_nearest_neighbours`, `--distance` и `--weighting`.
- Добавлено создание всех трёх поддерживаемых реализаций метрик и обоих
  способов взвешивания через параметры программы.
- В `KnnClassifier` и `KnnRegressor` добавлены открытые конструкторы, которые
  передают параметры общему базовому классу `Knn`.

### Проверка

- Исполняемый файл собран командой:

  `cmake --build build --target OOPLabs -j2`

- Интерфейс проверен из каталога сборки с параметрами `--k_nearest_neighbours 3`,
  `--weighting equal` и `--distance euclid`. Программа обучила классификатор,
  вывела пять случайных пар «предсказание/настоящее значение», затем штатно
  вернулась в меню и завершила работу.

## Эпизод 2. Случайные тестовые объекты

### Запрос

> Выводить пять случайных предсказаний вместо пяти первых.

### Изменения

В `train_and_predict` создаётся последовательность индексов тестовых
объектов, которая перемешивается генератором `std::mt19937`. Для вывода
выбираются первые пять перемешанных индексов, поэтому один объект не может
попасть в результат дважды.

## Эпизод 3. Повторный вывод предсказаний

### Запрос

> Сделать возможным несколько раз выводить предсказания без новых вызовов
> `transform`.

### Изменения

После разбиения датасета и предобработки матриц модель обучается один раз, а
предсказания для всей тестовой матрицы вычисляются один раз. Затем открывается
вложенное меню: каждый выбор пункта `1` заново перемешивает только индексы
тестовых объектов и выводит пять результатов из уже готового вектора
предсказаний. Пункт `0` возвращает пользователя в главное меню. Поэтому
повторный вывод не вызывает ни `transform`, ни повторное обучение, ни
повторное предсказание.

## Эпизод 5. Интеграция решающего пня в текстовый интерфейс

### Запрос

> Добавить в текстовый интерфейс возможность взаимодействия с решающим пнем
> аналогично kNN и обработать параметр `min_sample_leaf`.

### Изменения

В главное меню TUI добавлен пункт `Train decision stump and predict test data`.
Он:

1. делит датасет на обучающую и тестовую части;
2. повторно использует preprocessing обучающей части для тестовой;
3. кодирует категориальный target теми же кодами, что и в сценарии kNN;
4. выбирает `Gini` для категориального target и `Variance` для числового;
5. создаёт и обучает `DecisionStump` с параметром `min_sample_leaf`;
6. выводит выбранный признак и порог;
7. позволяет многократно выводить до пяти случайных предсказаний и настоящие
   значения до возврата в главное меню.

Параметр `--min_sample_leaf` теперь валидируется и сохраняется в глобальную
настройку модели. Значения меньше единицы отклоняются до загрузки датасета.

### Проверка

- Собран исполняемый файл `OOPLabs`.
- Запущены тесты через CTest.

## Эпизод 6. Тестирование решающего пня

### Запрос

> Добавить тесты нового функционала и разделить `lab2_tests.cpp` на тесты kNN
> и решающего пня.

### Изменения

Тесты `lab2_tests.cpp` разделены на две группы:

- kNN: расстояния, матрица, ошибки моделей, регрессия и классификация;
- DecisionStump: выбор признака и порога, предсказания, ошибки, ограничения
  `min_samples_leaf`, константные признаки и дубликаты значений.

В тестах реализована независимая наивная эталонная проверка. Она перебирает
допустимые пороги с полным пересчётом критерия и сравнивает с быстрой
реализацией для регрессии и классификации на случайных данных, используя
несколько значений `min_samples_leaf`.

При первом запуске тесты обнаружили обращение `nc_L.at(c)` к отсутствующему
счётчику класса в правой части критерия Джини. В быстрой реализации это
исправлено: отсутствующий счётчик левой части трактуется как нулевой.

Дополнительно тесты выявили, что при переходе к следующему признаку не
сбрасывалось количество объектов в левой части (`m_L`). Счётчик теперь
сбрасывается вместе с остальными агрегатами в `reset()`.

### Проверка

Сборка и CTest завершились успешно: все тесты `dataset_tests` и `lab2_tests`
пройдены.

## Эпизод 8. Примитивная наивная реализация в тестах

### Запрос

> Переделать наивную реализацию пня по примитивному алгоритму из условия без
> сортировки.

### Изменения

Эталонный алгоритм в `tests/decision_stump_tests.cpp` больше не сортирует
индексы. Для каждого признака он перебирает значения всех объектов как
кандидаты порога, каждый раз полным проходом раскладывает выборку на левую и
правую части и заново вычисляет критерий. Таким образом тестовая реализация
соответствует наивной сложности `O(d * n^2)`.
