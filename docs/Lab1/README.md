# Лабораторная работа 1

## Назначение программы

Программа загружает табличный датасет Autism Screening Adult, выводит его
сводную информацию и статистику признаков, выполняет базовую предобработку и
сохраняет результат в виде плотной числовой бинарной матрицы.

Исходный датасет описан в [README каталога data](../../data/README.md). Он содержит
704 объекта и 21 исходный признак. Это соответствует требованиям лабораторной
работы к размеру набора: допустим диапазон от 500 до 5000 объектов и от 6 до 25
признаков. Набор содержит числовые и категориальные признаки, пропуски и
целевой признак `Class/ASD`, пригодный для последующей задачи классификации.

## Формат входного файла

Загрузчик рассчитан на фактический формат выбранного датасета:

- CSV с разделителем `,`;
- первая строка содержит имена столбцов;
- файл имеет кодировку UTF-8;
- пропуск обозначается строкой `?`;
- значения с запятыми заключаются в одинарные кавычки в исходном наборе.

Специфичные для датасета обозначения находятся в конфигурационных константах
загрузчика: `ds::SPLIT` и `ds::MISSING_VALUE` в
[dataset.h](headers/dataset.h). Имена признаков не зашиты в алгоритмы:
загрузчик получает их из заголовка, а порядок и количество столбцов определяет
по файлу.

Загрузчик проверяет наличие файла, непустой заголовок, одинаковое количество
полей в строках и одинаковую длину всех столбцов. Повреждённые или
несогласованные входные файлы приводят к исключению с сообщением об ошибке.

## Представление данных

Данные хранятся по столбцам в `std::unordered_map`. Столбец представлен
`std::variant` из `NumericColumn` и `CategirialColumn`, а значения используют
`std::optional`. Поэтому пропуск хранится как `std::nullopt`, а не как
специальное числовое значение.

Такое представление сохраняет различие между числовыми и категориальными
данными до этапа предобработки и позволяет проверять длину каждого столбца
после загрузки.

## Автоматическое определение типа

Тип столбца определяется без списка имён:

1. пропуски `?` не участвуют в определении;
2. числовые значения разбираются как `double`;
3. числовой столбец считается действительно числовым, только если в нём больше
   двух различных значений;
4. остальные столбцы считаются категориальными.

Порог в два различных значения нужен, чтобы бинарные признаки `0/1` не
интерпретировались как количественные. В выбранном наборе по этому правилу
числовыми являются `age` и `result`; ответы на вопросы и остальные признаки
остаются категориальными. Это согласуется с предметным смыслом данных:
бинарные ответы не имеют естественного расстояния и порядка.

## Анализ и вывод

После загрузки программа выводит число объектов, число признаков, тип каждого
признака и статистику пропусков. Для выбранного числового признака выводятся:
минимум, максимум, среднее, дисперсия, квантили `q05`, `q25`, `q50`, `q75`,
`q95` и текстовая гистограмма из восьми интервалов. Для категориального
признака выводятся пропуски, категории и частотная гистограмма.

Статистика вычисляется до заполнения пропусков и хранится отдельно от исходных
столбцов. При некорректном номере признака программа сообщает об ошибке, не
завершая интерактивный цикл. Некорректный нечисловой ввод меню также
обрабатывается без падения.

## Предобработка

Перед сохранением выполняются следующие фиксированные шаги обязательной части:

1. пропуски числовых признаков заполняются медианой `q50`, рассчитанной по
   исходным данным;
2. пропуски категориальных признаков заменяются дополнительной категорией
   `__MISSING__`;
3. числовые признаки масштабируются по min-max:
   `(x - min) / (max - min)`;
4. категориальные признаки кодируются one-hot.

При one-hot-кодировании для каждой категории создаётся отдельный столбец с
именем вида `feature_category`. Порядок исходных признаков и категорий
детерминирован: признаки сортируются по имени, категории обрабатываются в
порядке первого появления в исходном столбце. Поэтому одинаковый вход
порождает одинаковую структуру матрицы.

Вырожденный случай числового признака с одинаковыми минимумом и максимумом в
текущем варианте не встречается в выбранном датасете. Для такого набора
масштабирование требует отдельного решения (например, заменить результат на
ноль); это ограничение явно не скрывается и должно быть обработано при смене
датасета.

Расширенное задание со звёздочкой — параметры командной строки, несколько
стратегий заполнения, масштабирования и кодирования — в текущей версии не
реализовано. Реализован обязательный вариант с фиксированными стратегиями,
описанными выше.

## Бинарный формат

Файл результата содержит:

1. `std::size_t n_rows`;
2. `std::size_t n_cols`;
3. для каждого столбца длину имени и байты имени;
4. массив значений `double` в порядке row-major:
   `data[row * n_cols + column]`.

Имена столбцов сохраняются вместе с матрицей, поэтому после one-hot-кодирования
можно восстановить соответствие между номером столбца и признаком.
Значения записываются непосредственно как `double`, без преобразования в текст.
После сохранения консольное приложение выводит размеры исходного CSV и
бинарного файла.

Формат предназначен только для учебного проекта: он зависит от размера
`std::size_t`, представления `double`, порядка байтов и не содержит версии
формата или контрольной суммы. Для обмена данными между разными платформами и
долгого хранения нужен явный переносимый формат.

## Тестирование

Тесты находятся в [tests/dataset_tests.cpp](../tests/dataset_tests.cpp),
собираются через CMake отдельной целью `dataset_tests` и регистрируются в
CTest. Проверяются:

- некорректные пути и повреждённые CSV;
- пустой CSV и CSV без записей;
- строки с лишним или недостающим полем;
- неодинаковая длина столбцов;
- неизвестные имена и индексы признаков;
- ошибка записи бинарного файла;
- усечённый бинарный файл;
- совпадение размеров, имён столбцов и каждого значения матрицы после
  сохранения и чтения.

Запуск из корня проекта:

```bash
cmake -S . -B build
cmake --build build
ctest --test-dir build --output-on-failure
```

Тестовый раннер не использует сторонний фреймворк: при ошибке он возвращает
ненулевой код, как предусмотрено условием лабораторной работы.
