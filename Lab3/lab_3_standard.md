## От соседей к плавному взвешиванию

kNN сначала выбирает ровно `k` объектов, остальные не влияют на ответ.
NW рассматривает все обучающие объекты, но уменьшает их влияние с расстоянием.
Параметр `h`, или bandwidth, задаёт масштаб этого уменьшения.

Для гауссова ядра:

$$
w_i(x)=\exp\left(-\frac{d(x,x_i)^2}{2h^2}\right),\qquad h>0.
$$

Нормировочный множитель гауссовой плотности не нужен: он сократился бы в
отношении. Это ядерное сглаживание по выбранному расстоянию, а не вычисление
полноценной многомерной плотности признаков.

В регрессии ответ — взвешенное среднее:

$$
\hat y(x)=\frac{\sum_i w_i(x)y_i}{\sum_i w_i(x)}.
$$

При небольшом `h` сильнее влияют ближайшие объекты. При большом `h` веса
сближаются, и ответ приближается к общему среднему. Совпадение с обучающим
объектом не означает точной интерполяции: при конечном `h` другие объекты всё
ещё участвуют. Если ближайших объектов несколько, их влияние учитывается вместе.

Для классификации считаются взвешенные доли классов:

$$
\hat p_c(x)=\frac{\sum_i w_i(x)\,\mathbf 1[y_i=c]}{\sum_i w_i(x)}.
$$

Метка выбирается по максимальной вероятности. Усреднять сами числовые коды
классов нельзя. Так одна и та же процедура весов используется в обеих задачах.

## Строки и столбцы матрицы: `MatrixSlice`

В работе 2 строка матрицы возвращалась через `operator[]` как `std::span`.
Теперь поддержите срезы по строкам и столбцам при обоих порядках хранения.
Матрица всегда принимает **два аргумента** в `operator()`: два индекса означают
элемент, один индекс и `std::nullopt` — целую строку или столбец.

```cpp
double value = X(i, j);          // значение элемента
X(i, j) = 2.0;                  // изменение элемента
auto row = X(i, std::nullopt);   // невладеющая строка i
auto col = X(std::nullopt, j);   // невладеющий столбец j
double a = row(j);              // тот же элемент X(i, j)
double b = col(i);              // тот же элемент X(i, j)
row(j) = 3.0;                   // меняет исходную матрицу
auto values = *row;             // span, только если строка непрерывна
```

При правильных индексах **любой из этих срезов создаётся при любом layout**.
Несоответствие направления среза порядку хранения не является ошибкой создания
среза. В частности, строка ColumnMajor и столбец RowMajor доступны через
`slice(k)`; исключение возникает только при попытке получить из неплотного
среза `span`. Направление всегда задаётся аргументами: матрица не подменяет
запрошенную строку столбцом в зависимости от layout.

### Перегрузки `operator()`

Для пропущенного индекса используйте тип `std::nullopt_t` из `<optional>`.
Он позволяет записывать срезы через `std::nullopt`, не создавая лишних случаев
с заполненным `std::optional<std::size_t>`. Тип результата выбирается при
компиляции по перегрузке, а не по значению индекса во время выполнения.

Допустимо написать `MatrixSlice<T>` для `T = double` и `T = const double`
либо два небольших класса. Ниже используется шаблонное обозначение.

```cpp
double& operator()(std::size_t row, std::size_t col) &;
const double& operator()(std::size_t row, std::size_t col) const &;

MatrixSlice<double> operator()(std::size_t row, std::nullopt_t) &;
MatrixSlice<const double> operator()(std::size_t row, std::nullopt_t) const &;

MatrixSlice<double> operator()(std::nullopt_t, std::size_t col) &;
MatrixSlice<const double> operator()(std::nullopt_t, std::size_t col) const &;
```

При двух числах возвращается ссылка на обычный `double`, а не промежуточный
объект. При сохранении результата в переменную `double` значение копируется.
Срез возвращается по значению и сам не владеет элементами.
Одноаргументный вызов `X(i)` и вызов с двумя `std::nullopt` не поддерживаются.
Метод `column()` для нового интерфейса не требуется.

Запретите получать срезы и ссылки из временного `Matrix`: к каждой нужной
перегрузке добавьте удалённые варианты с квалификаторами `&&` и `const &&`.
Одного `const &` недостаточно: он может связаться с временным объектом.

### Справка: `&`, `const &` и `&&` после метода

Символ `&` в конце объявления метода — **ref-квалификатор**. Он описывает,
у какого объекта разрешено вызвать метод, а не тип результата.

```cpp
MatrixSlice<double>
operator()(std::nullopt_t, std::size_t col) &;
```

Эта перегрузка вызывается у изменяемой матрицы-lvalue, например у переменной:

```cpp
Matrix matrix = load_matrix();
auto col = matrix(std::nullopt, 0); // matrix живёт после этого выражения
```

У `const &`-перегрузки объект матрицы константный; она возвращает срез
с константными элементами. `&&`-перегрузка предназначена для rvalue,
в частности временной матрицы, полученной из функции.

```cpp
auto bad = load_matrix()(std::nullopt, 0);
// Временная матрица была бы уничтожена в конце этой строки.
// Срез без владельца нельзя использовать.
```

Чтобы компилятор запретил такой вызов, объявите его удалённым:

```cpp
MatrixSlice<double>
operator()(std::nullopt_t, std::size_t col) && = delete;

MatrixSlice<const double>
operator()(std::nullopt_t, std::size_t col) const && = delete;
```

Аналогично добавьте удалённые `&&`/`const &&`-перегрузки для строки и доступа
к элементу. `= delete` означает ошибку компиляции при выборе этой перегрузки.
Удалённый `const &&` важен, потому что один `const &` сам по себе допускает
вызов у временного объекта. Срез при этом по-прежнему возвращается по значению;
его элементы остаются во внешней матрице.

### Интерфейс `MatrixSlice`

Ниже дан полный каркас интерфейса; тела методов реализуйте самостоятельно.
Достаточно поддержать `T = double` и `T = const double`.

```cpp
#include <cstddef>
#include <span>

enum class SliceAxis { Row, Column };

template<class T>
class MatrixSlice {
public:
    MatrixSlice() noexcept = default;
    MatrixSlice(T* data, std::size_t size,
                std::size_t stride, SliceAxis axis);

    std::size_t size() const noexcept;
    bool empty() const noexcept;
    std::size_t stride() const noexcept;
    SliceAxis axis() const noexcept;
    bool is_contiguous() const noexcept;
    T* data() const noexcept;

    T& operator()(std::size_t index) const noexcept;
    T& at(std::size_t index) const;
    std::span<T> operator*() const;
    std::span<T> as_span() const; // та же проверка, что у operator*

    MatrixSlice<const double> as_const() const noexcept;

private:
    T* data_ = nullptr;
    std::size_t size_ = 0;
    std::size_t stride_ = 1;
    SliceAxis axis_ = SliceAxis::Row;
};
```

`as_const()` создаёт читаемую оболочку над теми же элементами без копирования.
Он удобен, если функция принимает `MatrixSlice<const double>`, а у вызывающего
кода есть изменяемый срез. Для уже читаемого среза возвращается другая читаемая
оболочка. Можно реализовать безопасное неявное преобразование вместо этого
метода, но оно не требуется.

Для пустого среза `data_` должен быть **`nullptr`**. Конструктор с `size == 0`
сохраняет `nullptr` независимо от переданного указателя. Для непустого среза
проверяются ненулевой указатель и положительный шаг. Остальная корректность
буфера обеспечивается владельцем — матрицей.

### Состояние и доступ к элементам среза

Матрица владеет одним плоским массивом. Физическое смещение элемента:

- RowMajor: `i * cols + j`;
- ColumnMajor: `j * rows + i`.

`MatrixSlice` хранит указатель на первый элемент, число элементов, положительный
шаг `stride` в элементах, а не байтах, и направление среза.

Направление доступно только для чтения через `SliceAxis axis() const noexcept`.
Само поле сделайте закрытым, без публичного setter: вызывающий код не должен
менять строку на столбец. Публичное `const`-поле необязательно; оно затрудняет
обычное присваивание срезов. Необходимы также `size()`, `empty()`, `stride()`,
`is_contiguous()`, `operator()(index)`, проверяемый `at(index)` и `operator*()`.

Элемент с номером `k` находится по смещению `k * stride`. `slice(k)` возвращает
`T&` и работает независимо от непрерывности. Изменение через изменяемый срез
изменяет матрицу; создание и копирование оболочки не копируют элементы.

| Срез | Размер | Шаг в RowMajor | Шаг в ColumnMajor |
|---|---|---|---|
| `X(i, std::nullopt)` — строка | `cols` | 1 | `rows` |
| `X(std::nullopt, j)` — столбец | `rows` | `cols` | 1 |

Как у `span`, константность оболочки и элементов различается:
`const MatrixSlice<double>` всё ещё позволяет менять `double`,
`MatrixSlice<const double>` — не позволяет. Константная матрица всегда
возвращает второй вариант. Преобразование изменяемого среза в читаемый
допустимо, обратное — нет.

### Зачем нужен `const MatrixSlice`, если данные отдельно?

У среза есть две независимые вещи: оболочка с указателем/размером/шагом и
элементы матрицы. Обычную оболочку можно присваиванием перенаправить на другой
срез; константную оболочку — нельзя:

```cpp
auto row = X(0, std::nullopt);
row = X(1, std::nullopt);          // теперь row обозначает другую строку

const auto fixed_row = X(0, std::nullopt);
// fixed_row = X(1, std::nullopt); // ошибка: нельзя заменить оболочку
fixed_row(0) = 5.0;               // можно, если X не константная
```

Последняя запись меняет элемент матрицы, а не указатель, размер или шаг среза.
Поэтому `operator()(index) const` возвращает `T&`: при `T=double` это изменяемая
ссылка, при `T=const double` — константная. `const MatrixSlice<double>` фиксирует
оболочку; `MatrixSlice<const double>` запрещает изменение элементов.
Именно второй тип возвращает константная матрица.
Писать `const` перед каждой локальной переменной-срезом не обязательно.

### Получение `span` через `operator*()`

`operator*()` возвращает `std::span<T>` по значению, без копирования элементов.
Это явно вызванный оператор, а не неявное преобразование. Дополнительно можно
дать ему именованный аналог `as_span()`.

- При `stride == 1` срез непрерывен, преобразование успешно.
- Пустой и одноэлементный срезы также могут дать `span` независимо от шага.
- Если элементов больше одного и `stride != 1`, `operator*()` бросает
  исключение вашей иерархии, например `NonContiguousSliceError`, производное
  от `std::logic_error`. Сам срез остаётся пригоден для доступа через `slice(k)`.

Например, для ColumnMajor при числе строк и столбцов больше одного:

```cpp
auto row = X(0, std::nullopt); // успешно: шаг равен числу строк
double x = row(1);            // успешно: доступ с шагом
auto row_span = *row;         // исключение: строка неплотная

auto col = X(std::nullopt, 0); // успешно: шаг равен 1
auto col_span = *col;         // успешно: span столбца
```

Не формируйте `span`, который захватывает промежуточные чужие элементы.
Не создавайте скрытую временную копию строки или столбца ради преобразования.
Свойства `axis()` и `is_contiguous()` независимы: направление среза не меняется
при невозможности получить `span`.

### Границы, пустые срезы и время жизни

`X(i,j)` и `slice(k)` не проверяют границы, как ранее `operator[]`;
`at()` проверяет их и бросает исключение. Создание среза проверяет номер
запрошенной строки или столбца, но не требует соответствия layout.
Пустая строка допустима в матрице `rows > 0, cols == 0`, пустой столбец —
при `rows == 0, cols > 0`. Из пустого среза возвращается пустой `span`.
Для пустого среза явно сохраняйте указатель `nullptr`; не вычисляйте
адрес элемента, которого нет.

Срез становится недействительным после уничтожения матрицы либо операции,
которая заменяет/перераспределяет её буфер. Не сохраняйте срезы и полученные
из них `span` дольше владельца. Отрицательные шаги, прямоугольные подматрицы,
произвольные Python-срезы с границами и свои STL-итераторы не требуются.

Способ работы расстояний и других вычислительных функций выберите сами.
Можно всегда обращаться к элементам через `slice(k)`. Можно проверять layout
или `is_contiguous()` и для непрерывного среза использовать `span` как
оптимизированный путь, а для неплотного — доступ с шагом. Допустим и явно
организованный перевод данных модели в удобный layout; его копирование и
время жизни должны быть понятны. Оба исходных layout должны поддерживаться.
Согласуйте интерфейс `IDistance` с выбранным решением и объясните его в README.
Статистические функции над непрерывными массивами могут сохранить `span`.

Старый `operator[]` можно оставить для совместимости. Если он сохраняет
прежний возврат строки как `span`, он должен явно отклонять неплотные строки.
Новый интерфейс срезов работает через двухаргументный `operator()`.
Единый логический доступ не устраняет различия производительности layout
и не требует одновременно хранить две копии каждой матрицы.

class IModel {

    virtual std::vector<double> predict(const Matrix& X) const = 0;

class IRegressor : public IModel {
    // Общий контракт регрессоров; дополнительные методы сейчас не нужны.

Разделение позволяет передавать регрессоры и классификаторы в разные
композиции без проверки конкретных классов во время выполнения. Не добавляйте
в интерфейсы методы только ради того, чтобы они не были пустыми.

Вектор `y` и результаты `predict` остаются `double` для совместимости с работой 2.
В классификации эти числа обозначают фиксированные метки классов.
Способ представления выбирайте сами: например, `0`, `1`, `2` для трёх классов.
В `Dataset` или другом подходящем месте должно сохраняться соответствие,
позволяющее восстановить исходные обозначения из датасета — например,
`0 -> "бензин"`, `1 -> "дизель"`. Предсказанная метка должна принадлежать
набору классов модели; усреднять номера классов как числовые отклики нельзя.

### Новый метод `classes()`

В работе 2 этот метод **не требовался**. В работе 3 мы добавляем его вместе
с `predict_proba`, чтобы понимать, какой класс означает каждый столбец
матрицы вероятностей.

Например, `classes()` вернул `[0, 1]`, а строка `predict_proba(X)` равна
`[0.2, 0.8]`. Значит, вероятность метки 0 равна 0.2, метки 1 — 0.8;
приложение восстанавливает их исходные названия по словарю датасета.
Метод не вычисляет вероятности и не относится к C++-классам: он просто
предоставляет список меток в порядке столбцов.

`predict_proba(X)` возвращает матрицу `число объектов × число классов`.
Столбец `c` относится к `classes()[c]`. Классы отсортированы по возрастанию;
при равенстве максимальных вероятностей выбирается меньшая исходная метка.
Вероятности неотрицательны, сумма строки равна единице с численной точностью.
`classes()` до обучения, как и `predict`, сообщает об ошибке. Полученный из
`classes()` span может стать недействительным после повторного `fit`.

Разделите обязанности методов:

| Метод | Ответственность |
|---|---|
| Конструктор | Сохранить гиперпараметры и зависимости; проверить ограничения, не зависящие от данных |
| `fit` | Проверить выборку и совместимость с параметрами; построить обученное состояние |
| `predict` / `predict_proba` | Проверить обучение и размерность входа; вычислить ответы без изменения модели |

После создания модели гиперпараметры не меняются: для другой конфигурации
создаётся новый экземпляр. Конструктор не читает датасет и не выполняет обучение.
Объект после конструктора корректен, но ещё не обучен. Неположительный bandwidth
или нулевой `min_samples_leaf` проверяются сразу; ограничение `k <= n_train`
можно проверить только в `fit`.

Повторный успешный `fit` полностью заменяет прежнее обученное состояние,
включая классы и число признаков. При ошибке объект не остаётся частично
обученным: допустимы сохранение прежнего состояния или явный переход в
необученное состояние. Выберите вариант, опишите и проверьте его.

Для небольших выборок курса рекомендуется владеть сохранёнными обучающими
данными. Одна необходимая копия при `fit` допустима; случайные повторные копии
нет. Данные, нужные после `fit`, не могут ссылаться на локальную матрицу,
временный `span` или уже уничтоженный внешний объект.

## Требования к реализации NW

1. Реализуйте `NwRegressor` и `NwClassifier`. Расчёт расстояний и весов общий;
   конкретная агрегация относится к задаче. Не дублируйте полный проход по
   выборке в двух классах.
2. Метрика передаётся извне через уточнённый `IDistance`. Сохраните евклидову,
   манхэттенскую и Чебышёва из работы 2. Модель не выбирает их через `switch`.
3. Обязательно одно гауссово ядро. Отдельный `IKernel` допустим, но не обязателен
   при единственной реализации. Дополнительные ядра не нужны для зачёта.
4. `h` — конечное положительное число, проверяется в конструкторе. Обучающие
   данные и классы появляются в `fit`; `fit` NW не подбирает bandwidth.
5. Обновите `KnnRegressor` и `KnnClassifier` до новых интерфейсов.
   `predict_proba` kNN возвращает нормированные голоса с выбранными весами.
   При нулевых расстояниях в режиме обратных весов голосуют только выбранные
   совпавшие соседи; неоднозначные совпадения разрешаются документированно.

### Численная устойчивость

При малом `h` прямое вычисление всех экспонент может дать нули, хотя точный
гауссов вес положителен. Нужно нормировать веса устойчиво. Для представимых
логарифмов весов используйте:

$$
a_i=-d_i^2/(2h^2),\qquad
\tilde w_i=\exp(a_i-\max_j a_j).
$$

Общий множитель сокращается, а наибольший вычисленный вес равен единице.
Нельзя просто добавить произвольное epsilon в знаменатель: это меняет формулу.

Учтите, что для экстремальных, но конечных входов уже квадрат расстояния или
отношение к `h` могут переполниться. Нельзя вычитать `-inf - (-inf)` и считать
такой ответ устойчивым. Для диапазона, не поддерживаемого вашей арифметикой,
допустимо понятное численное исключение; обычные малые `h`, при которых
обнуляются только прямые экспоненты, должны успешно обрабатываться.
Никаких молчаливых NaN и деления на ноль.

Матрицу расстояний `n_test × n_train` хранить не нужно. Обрабатывайте запросы
по одному. Внутри запроса допустим буфер `O(n_train)` и два прохода либо
другая объяснимая устойчивая схема.

## Консольный сценарий

Приложение загружает данные, создаёт выбранную модель, обучает её на обучающей
части и выводит несколько тестовых откликов рядом с предсказаниями.
Для классификации дополнительно показываются классы и их вероятности.
В одном приложении можно выбрать kNN или NW без переписывания вычислительного
сценария. Параметры можно задавать аргументами либо в одном месте конфигурации.

Покажите влияние нескольких `h` на простой синтетической выборке.
Меняться должны результаты на подходящем примере; не требуется, чтобы
произвольная смена параметров меняла каждый ответ реального датасета.

## Тесты

**Код всех перечисленных тестов и генерацию тестовых данных можно поручить
ИИ-агенту. Студент проверяет ожидаемые ответы и понимает назначение тестов.**

Обязательно проверьте:

- одинаковые логические матрицы в RowMajor и ColumnMajor: `X(i,j)`, `X(i, std::nullopt)(j)`
  и `X(std::nullopt, j)(i)` дают одинаковые значения;
- изменение через неконстантный срез меняет исходную матрицу; чтение из
  константной матрицы не позволяет запись; при необходимости используйте
  `static_assert` над типами выражений;
- срезы обоих направлений создаются при любом layout; `slice(k)` работает
  и для неплотного среза, а `axis()` сохраняет правильное направление;
- `*slice` успешен для непрерывных, пустых и одноэлементных представлений,
  а для неплотного представления длины больше одного бросает нужное исключение;
- размеры, границы и оба layout на прямоугольной, а не только квадратной матрице;
- расстояния и предсказания kNN сохраняются после рефакторинга;
- NW на двух объектах с равноудалённым запросом возвращает среднее откликов;
- пример с неравными расстояниями проверяет именно гауссовы веса;
- константный отклик остаётся константным, ответ лежит между минимумом и
  максимумом обучающих откликов с допустимой погрешностью;
- вероятности правильны на ручном примере с метками `10` и `42`, при одном
  классе и при ничьей; порядок `classes()` согласован со столбцами;
- малый `h`, дубликаты объектов с разными откликами и повторный `fit`;
- все ошибочные ситуации и ноль тестовых объектов из общих требований.

Сравнивайте вещественные результаты с абсолютным/относительным допуском,
а не побитовым равенством. Не разыменовывайте заведомо висячий срез ради теста:
проверяйте запрет опасных вызовов и корректность времени жизни.

## Общие требования и сдача

- C++20, CMake, отдельные цели ядра, приложения и тестов; сборка без
  предупреждений при `-Wall -Wextra`.
- Проверки зарегистрированы в CTest, в Debug подключены ASan и UBSan.
- Ядро не печатает сообщения пользователю; ошибки сообщаются исключениями
  существующей иерархии. Приложение перехватывает их по ссылке и возвращает
  ненулевой код при неуспехе. Исключения в тестах перехватываются для проверки.
- Новая модель подставляется через `IModel` и соответствующий интерфейс задачи;
  вычислительный код приложения не содержит проверок конкретного класса.
- Для `fit` проверяются непустая выборка и ненулевое число признаков,
  совпадение размеров `X` и `y`, конечность входных чисел. При предсказании
  проверяются обучение, число признаков и конечность входа. Ноль тестовых
  объектов допустим: возвращается пустой вектор или матрица `0 × C`.
- Нет висячих представлений, утечек, общей изменяемой глобальной памяти.
- Сохраняется история осмысленных коммитов и обновляется документация интерфейсов.

Сдаются репозиторий-продолжение предыдущей работы, README с устройством классов,
описанием владения и рефакторинга, командами сборки и запуска, примерами вывода,
тесты и `docs/agent_log/lab_3.md`. Актуализируйте `AGENTS.md`: зафиксируйте
разрешённые задачи и самостоятельную часть именно этой работы.
