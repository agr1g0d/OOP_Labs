# Лабораторная работа 4. Случайный лес — трек со звёздочкой

Этот документ объединяет объяснения и условие и заменяет обычную работу 4.
Используются пень и CART из сложного трека работ 2–3. Реализовывать kNN,
NW и обычный бэггинг из другого трека для сдачи этого варианта не требуется.
Звёздочка учитывается для автомата по правилам курса.

## Цель и границы соответствия sklearn

Реализовать random forest для регрессии и классификации по базовой схеме
`sklearn.ensemble.RandomForestRegressor` / `RandomForestClassifier`:
bootstrap объектов, CART с лучшим порогом на случайных признаках в каждом узле,
независимые деревья, усреднение ответов/вероятностей.

Ориентир для проверяемых деталей — sklearn 1.8.0, его документация и исходный
код. Требуется соответствие алгоритмическим правилам ниже, а не повторение
всего API или служебной реализации библиотеки. C++-код использует `double`;
переход sklearn к float32, его RNG и точный порядок разрешения ничьих не
копируются. При одном seed реализации не обязаны строить одинаковые леса.

Вход — конечная плотная числовая матрица из предыдущих работ и отдельный
отклик. Пропуски уже обработаны. Не требуются sparse-матрицы, multi-output,
нативная обработка NaN, веса классов, пользовательские sample weights,
монотонные ограничения, pruning, warm start, OOB-оценка или impurity-based
feature importance. Кеширование константных признаков, специализированная
сортировка, Cython и прочие оптимизации библиотеки тоже не нужны.
Базовые ограничения глубины и размеров узлов сохраняются.

## Почему лес отличается от одного дерева

Глубокое дерево может заметно меняться при замене части обучающих объектов.
Лес строит несколько деревьев с разной случайностью и усредняет их ответы.
Если ошибки деревьев различаются, усреднение может сделать результат устойчивее.
Улучшение на любом конкретном датасете не гарантируется.

Есть два разных источника случайности:

1. Для каждого дерева выбирается bootstrap-выборка объектов с возвращением.
2. В каждом внутреннем узле заново выбираются признаки для поиска разбиения.

Дерево получает все исходные признаки. Фиксированное подмножество столбцов
один раз на всё дерево не заменяет выбор признаков в каждом узле.
В этом отличие леса от ансамбля с адаптером признаков из обычного трека.
Порог выбирается **лучший**, а не случайный: иначе получился бы другой метод,
ближе к Extra Trees.

## Обязательные параметры

| Параметр | Требование |
|---|---|
| `n_estimators` | Число деревьев, не меньше 1; значение по умолчанию 100 |
| `bootstrap` | `true` по умолчанию; при `false` все деревья получают весь набор объектов |
| `max_samples` | Необязательное целое число извлечений `m` от 1 до `n`; отсутствие означает `m=n` |
| `max_features` | Режим `All`, `Sqrt` или явное целое число от 1 до `d` |
| `max_depth` | Необязательный положительный предел глубины; отсутствие означает рост до других условий остановки |
| `min_samples_split` | Целое не меньше 2, по умолчанию 2 |
| `min_samples_leaf` | Целое не меньше 1, по умолчанию 1 |
| `random_state` | Явный целочисленный seed |
| `n_jobs` | Число одновременно выполняемых задач, не меньше 1 |

Для классификации по умолчанию `max_features = Sqrt`, то есть
`q = max(1, floor(sqrt(d)))`; для регрессии — `All`, то есть `q=d`.
Дробные варианты `max_samples`, `min_samples_*`, `max_features` и режим `log2`
не требуются. При `bootstrap=false` заданный `max_samples` считается ошибкой,
как в выбранном подмножестве API sklearn.

Критерии фиксированы: Джини для классификации и squared error для регрессии.
Случайный лес использует те же CART и поиск порога из работы 3;
отдельно переписывать алгоритм дерева для леса нельзя.
Уточните CART: он должен поддерживать отсутствие ограничения глубины и
не запрещать допустимое разбиение только потому, что его улучшение равно нулю.
При значении по умолчанию `min_impurity_decrease=0` sklearn допускает нулевое
улучшение; специальный положительный порог в этом задании не нужен.

## Как доработать CART из работы 3

Дерево из третьей работы — основа леса, но его **нужно расширить**.
Оно не обязано остаться неприкосновенным. Отдельный второй алгоритм CART
для леса не пишется: обычное дерево и дерево леса используют одну реализацию.

| Часть CART | Что остаётся | Что меняется в работе 4 |
|---|---|---|
| Узлы и владение | Внутренний узел с признаком, порогом и двумя потомками; лист с ответом | Новая структура узлов не нужна |
| Рекурсивный рост | Проверить остановку, найти порог, разделить индексы, построить потомков | В узле дополнительно известны кратности и случайный порядок признаков |
| Объекты узла | Список исходных индексов | В корень включаются только индексы с положительной кратностью; отдельно считается сумма кратностей |
| Критерий | Сортировка по признаку и один проход по порогам | Суммы и частоты обновляются с учётом кратности переносимого объекта |
| Ограничения размеров | `min_samples_split` и `min_samples_leaf` | Проверяются по числу разных исходных индексов, не по сумме кратностей |
| Поиск признака | Обычное дерево может рассматривать все признаки | Дерево леса получает новый случайный набор/порядок в каждом узле |
| Ответ листа | Среднее или доли классов | Эти величины теперь взвешиваются bootstrap-кратностями |
| Предсказание | Проход от корня по `<=` до листа | Алгоритм прохода не меняется |

Удобный путь рефакторинга:

1. Обычный `fit` оставить в общем интерфейсе и считать все кратности равными 1.
2. Добавить метод `fit_with_counts` для дерева внутри леса. Он вызывает тот же
   построитель, но передаёт целые кратности, полученные bootstrap.
3. Расширить существующий `SplitFinder` параметром кратностей и обновить
   агрегаты внутри его прежнего прохода по отсортированным значениям.
4. Выделить поиск на одном признаке. Обычное дерево перебирает все признаки,
   дерево леса — выбранные случайно; код поиска порога один и тот же.
5. Параметры просмотра признаков и seed задать дереву при создании. При каждом
   обучении его генератор заново инициализируется этим seed.

Например, для регрессора интерфейс можно расширить так. `TreeParams` содержит
уже знакомые ограничения глубины и размеров узлов:

```cpp
enum class FeatureMode { All, Sqrt, Count };

struct FeatureSearchParams {
    FeatureMode mode = FeatureMode::All;
    std::size_t count = 1; // используется только для Count
};

class CartRegressor : public IRegressor {
public:
    CartRegressor(TreeParams tree_params,
                  FeatureSearchParams feature_search = {},
                  std::uint32_t random_state = 0);

    void fit(const Matrix& X, std::span<const double> y) override;
    void fit_with_counts(const Matrix& X, std::span<const double> y,
                         std::span<const std::size_t> counts);
    std::vector<double> predict(const Matrix& X) const override;

    // Прежние узлы и общий построитель дерева сохраняются.
};
```

У `CartClassifier` добавляется аналогичный метод, а `predict_proba` и
`classes()` сохраняются. В `fit_with_counts` длина `counts` равна числу
исходных строк, нулевые значения разрешены, но хотя бы одно должно быть
положительным. Это служебное расширение дерева, а не изменение `IModel`.
Не нужно реализовывать API произвольных вещественных весов.

Для обычного дерева режим `All` и единичные кратности дают прежнее поведение.
После рефакторинга старые тесты должны продолжать проходить. Для леса меняются
передаваемые данные и политика поиска, а не весь алгоритм построения.

## Bootstrap: кратность и число объектов — разные величины

При `bootstrap=true` сделайте `m` равновероятных извлечений исходных индексов
с возвращением. После bootstrap некоторые исходные объекты или даже целый редкий класс
могут не попасть в выборку дерева. **Неполное представительство исходной
выборки — нормальный результат bootstrap, а не ошибка алгоритма.**
Не добавляйте недостающие классы вручную и не повторяйте извлечение,
пока не получите их все: это изменило бы способ формирования выборки.

В sklearn повторения представлены весами-кратностями. Для соответствия
существенны не только критерии, но и ограничения размеров узлов.
Сохраните простой массив целых кратностей `count[i]`. В узел входят исходные
индексы с положительной кратностью. Здесь:

- `s` — число различных **исходных индексов** в узле;
- `W = sum(count[i])` — суммарная кратность объектов узла.

Одинаковые значения признаков у разных исходных строк не означают один объект.

`min_samples_split` и `min_samples_leaf` проверяются по `s` и соответствующим
числам исходных индексов у потомков, а критерии, средние и частоты используют
кратности. Например, индексы bootstrap `[0, 0, 1, 1]` дают два объекта с весами
2 и 2. При `min_samples_leaf=2` разделить их на два однообъектных листа нельзя,
хотя общее число извлечений равно четырём.

Простое создание четырёх физических строк и подсчёт ограничений по ним может
дать другое дерево, чем sklearn. Целочисленные кратности здесь нужны для
семантики, а не ради сложной оптимизации.

При `bootstrap=false` у каждой исходной строки кратность 1.
Для дерева вне леса обычный `fit` также эквивалентен единичным кратностям.
Не меняйте общий `IModel::fit`: можно добавить внутренний метод обучения CART
с кратностями или передать их в общий построитель дерева.
Общий публичный API произвольных пользовательских весов реализовывать не нужно.

### Взвешенные агрегаты

В регрессии:

$$
S=\sum_i count_i y_i,\qquad W=\sum_i count_i,
\qquad \hat y_{leaf}=S/W.
$$

Для выбора порога максимизируется `S_L²/W_L + S_R²/W_R`.
При переносе исходного объекта с кратностью `w` обновляйте `S_L += w*y`,
`W_L += w`, а счётчик различных объектов увеличивайте только на 1.

Для классификации `n_c` — сумма кратностей объектов класса `c`,
`A=sum(n_c²)`. Критерий выбора порога — максимум `A_L/W_L + A_R/W_R`.
При переносе объекта класса `c` с кратностью `w`, если прежние счётчики
класса слева и справа равны `a` и `b`:

$$
A_L\mathrel{+}=2aw+w^2,\qquad
A_R\mathrel{+}=-2bw+w^2.
$$

Обновление всё ещё `O(1)` на перенос. Считайте выражения в подходящем типе:
беззнаковое вычитание в обновлении правой части не должно переполняться.
Частота класса в листе равна `n_c/W`.

## Случайные признаки и лучший порог в узле

### Обновлённый интерфейс `SplitFinder`

`Split` с полями `feature`, `threshold`, `score` сохраняется из работы 3.
В метод `find_best` добавляется необязательный последний параметр `counts`.
Пустой span означает единичные кратности; непустой индексируется исходным
номером строки и должен иметь длину `X.rows()`.

```cpp
struct FeatureSplitResult {
    bool is_constant;
    std::optional<Split> best;
};

class SplitFinder {
public:
    std::optional<Split> find_best(
        const Matrix& X,
        std::span<const double> y,
        std::span<const std::size_t> object_ids,
        std::span<const std::size_t> feature_ids,
        SplitCriterion criterion,
        std::size_t min_samples_leaf,
        std::span<const std::size_t> counts = {}
    ) const;

    FeatureSplitResult find_for_feature(
        const Matrix& X,
        std::span<const double> y,
        std::span<const std::size_t> object_ids,
        std::size_t feature,
        SplitCriterion criterion,
        std::size_t min_samples_leaf,
        std::span<const std::size_t> counts = {}
    ) const;
};
```

Существующее объявление `find_best` заменяется расширенным, а не сохраняется
рядом второй неоднозначной перегрузкой. Старые вызовы без последнего аргумента
продолжают работать благодаря значению по умолчанию.

`find_for_feature` содержит знакомые сортировку и проход по порогам для одного
столбца. `find_best` вызывает его для разрешённых признаков и выбирает лучший
результат. Разделение нужно лесу, чтобы просматривать признаки в случайном
порядке и отдельно распознавать константные.

Вызов из обычного дерева:

```cpp
auto split = finder.find_best(
    X, y, node_ids, all_features, criterion, min_samples_leaf
);
```

Вызов при проверке одного кандидата в узле дерева леса:

```cpp
auto candidate = finder.find_for_feature(
    X, y, node_ids, feature, criterion, min_samples_leaf, counts
);
```

`node_ids` содержит каждый исходный индекс не больше одного раза;
повторения представлены в `counts`. Принадлежность объектам левого/правого
потомка по-прежнему определяется одним сравнением признака с порогом.


Выделите заменяемую политику просмотра признаков: обычное дерево использует
все признаки, дерево леса — случайный порядок с бюджетом `q`.
Политика задаёт признаки, а существующий `SplitFinder` ищет лучший порог.
Можно использовать небольшой интерфейс или callable. Не создавайте отдельное
дерево-копию класса CART и не вставляйте случайность в критерий.

Для простого варианта достаточно в каждом узле независимо перемешать
индексы всех `d` признаков и рассматривать их в полученном порядке без повторов.
Обычно просматриваются первые `q`. На просмотренных признаках перебираются
все допустимые пороги по правилам работы 3, с учётом кратностей и размеров
потомков. Выбирается лучший результат.

Есть важная деталь sklearn: константные признаки не должны исчерпать весь
поиск, если ни один неконстантный ещё не рассмотрен. Если первые `q`
просмотренных признаков константны в текущем узле, продолжите по случайному
порядку до первого неконстантного или исчерпания всех признаков.
Поэтому `max_features` не является безусловным жёстким пределом просмотренных
признаков. Кешировать константность от родителя не требуется.

Если среди просмотренных неконстантных признаков нет порога, допустимого по
размерам потомков, получается лист. Не нужно расширять поиск до нахождения
порога любой ценой после рассмотрения неконстантного признака: это отдельное
отличие от продолжения из-за одних констант.

Повторяющиеся значения признака не разделяются порогом. Порог должен
маршрутизировать объекты так же, как они учитывались в критерии.
Ничьи можно разрешать детерминированно по индексу признака и порогу;
это может отличаться от случайного выбора sklearn при одинаковых оценках.

## Ответ леса и отсутствующие классы

`RandomForestRegressor` реализует `IRegressor`, `RandomForestClassifier` —
`IClassifier`. Лес владеет деревьями; наследоваться от одного дерева не нужно.
Базовые CART получают конфигурацию роста и политику признаков.
Выборка объектов, кратности и seed принадлежат элементу ансамбля, а не глобальной
переменной. Общую исходную матрицу можно безопасно читать из разных задач.

Для регрессии результат — среднее предсказаний деревьев:

$$
\hat y(x)=B^{-1}\sum_{b=1}^{B}\hat y_b(x).
$$

Для классификации, как в sklearn, усредняются **вероятности**, а не метки:

$$
\hat p_c(x)=B^{-1}\sum_{b=1}^{B}\hat p_{b,c}(x),
\qquad \hat c(x)=\operatorname*{argmax}_c\hat p_c(x).
$$

Вероятности дерева — доли классов в достигнутом листе с учётом bootstrap-
кратностей. Если два дерева дают классу A вероятность 0.51, а третье — 0,
среднее равно 0.34: голосование по готовым меткам выбрало бы другой ответ.
Такой пример обязательно включите в тесты.

Глобальный порядок классов строится по всему `y_train`. Если в bootstrap
дерева нет класса, оно даёт этому классу нулевую вероятность. Можно хранить
в деревьях сразу глобальную схему или согласовывать столбцы при агрегации.
Ничья разрешается меньшей исходной меткой. `classes()` и форма результата
не меняются от запроса к запросу.

## Жизненный цикл, воспроизводимость и параллельные вычисления

Конструктор сохраняет гиперпараметры и зависимости и проверяет ограничения,
не требующие данных. `fit` проверяет выборку и строит весь ансамбль заново;
модели не накапливаются при повторных вызовах. Для другой конфигурации
создаётся новый объект. `predict` и `predict_proba` обученное состояние
не меняют. При ошибке обучения частично построенный ансамбль не должен
считаться обученным: сохраните прежнее состояние или явно сбросьте обучение,
опишите и проверьте выбранное правило.

### Разные seed для разных деревьев

**Каждое дерево леса должно получать свой seed, отличный от seed других
деревьев. Один общий seed леса используется для воспроизводимого создания
этих разных seed, а не передаётся всем деревьям без изменений.**

**Разные элементы ансамбля должны обучаться с разными seed. Нельзя всем
моделям передать один и тот же `random_state` и ожидать разного bootstrap.**

Для обычного трека это разные seed генерации выборок объектов и признаков;
для леса — также генерации признаков в узлах дерева. Сначала по общему
`random_state` и номерам элементов подготовьте их разные seed в фиксированном
порядке. Можно сформировать список уникальных seed, проверяя повторения.
Каждый элемент получает собственный `std::mt19937`; общий изменяемый RNG
между потоками не используется.

Одинаковые вход, параметры и общий seed должны воспроизводить планы и ответы
в одном окружении независимо от числа потоков. Повторный `fit` начинает
генерацию заново, а не продолжает прежнее состояние RNG. Другой seed может,
но не обязан менять каждый ответ на простых данных. Побитового совпадения
между Python и C++ или разными стандартными библиотеками не требуется.

### Распараллеливание только через `std::jthread`

Реализуйте последовательное и параллельное обучение элементов ансамбля,
а также параллельное получение их предсказаний. Для создания потоков в этой
работе используется **только `std::jthread` из C++20**.
`n_jobs >= 1` ограничивает число рабочих потоков. При `n_jobs == 1`
используйте последовательный путь, при числе моделей меньше `n_jobs`
не создавайте лишние потоки.

Достаточно назначить каждому рабочему потоку несколько номеров моделей,
например `worker_id`, `worker_id + p`, `worker_id + 2*p`, где `p` — число
рабочих потоков. Универсальная очередь задач и собственный планировщик
не требуются. Один поток на каждую модель без ограничения `n_jobs` не подходит.

`std::jthread` при уничтожении ожидает завершения своего потока. Но результат
нельзя суммировать раньше этого ожидания: ограничьте группу потоков отдельным
блоком или явно вызовите `join()` у каждого перед чтением результатов.

Правила:

- исходная матрица и отклики доступны рабочим задачам только для чтения;
- элемент ансамбля и его генератор изменяет только один поток;
- контейнеры моделей, результатов и ошибок подготовлены до запуска потоков;
  совместного `push_back` нет;
- каждая задача пишет в своё место результата, а финальное среднее считается
  в порядке номеров моделей, а не порядка завершения;
- все захваченные по ссылке данные живут до завершения потоков;
- вложенная модель не использует общий изменяемый рабочий буфер без защиты;
- исключение перехватывается **внутри** рабочей функции и сохраняется через
  `std::current_exception()` в заранее подготовленную ячейку
  `std::exception_ptr` этой задачи; после завершения всех потоков ошибка
  передаётся вызывающему коду через `std::rethrow_exception()`.

Сам по себе `std::jthread` не передаёт исключения между потоками и не устраняет
гонки данных. Распараллеливать одновременно элементы ансамбля, отдельные
объекты и внутренние циклы расстояний не требуется: достаточно верхнего уровня.

**Написание кода с `std::jthread`, обработку ошибок потоков и его отладку
можно поручить ИИ-агенту. Итоговый код студент обязан понимать и уметь объяснить.**
До этого самостоятельно определите независимые задачи, владельцев данных,
правило seed и порядок агрегации; сначала проверьте последовательный вариант.

### Измерение времени

Измеряйте Release-сборку без санитайзеров на одинаковых данных и параметрах.
Подготовку данных, `fit` и пакетный `predict` измеряйте отдельно; загрузку CSV
не включайте в предсказание. Сделайте несколько повторов и сообщите медиану,
размеры данных, параметры, число потоков, компилятор и компьютер.

Сравните `n_jobs=1` и хотя бы одно большее значение. Ускорение — `T_1/T_p`.
Линейного выигрыша не требуется: на небольшой задаче затраты запуска потоков
могут перевесить пользу. Отсутствие ускорения объясните, не скрывайте его.

## Программа и тесты

Приложение обучает обычное CART и лес на одной обучающей части, показывает
параметры, несколько предсказаний и вероятности, размеры деревьев, времена
обучения и предсказания. Для диагностики достаточно MAE в регрессии или
accuracy в классификации, посчитанной в приложении; отдельная система метрик
и подбор параметров пока не требуются. Можно показать изменение числа
деревьев и `max_features` на синтетическом примере.

Минимальные проверки:

- контролируемый bootstrap проверяет кратности и ограничения размеров по
  исходным индексам; взвешенные критерии сравниваются с медленным подсчётом;
- сохранённый массив кратностей не меняется из-за порядка потоков;
- обычный CART при единичных кратностях совпадает с версией работы 3;
- политика признаков вызывается заново в разных узлах; дерево не ограничено
  одним набором столбцов на всё время обучения;
- при первых константных кандидатах проверяются дополнительные признаки;
- пороги выбираются лучшими среди рассмотренных, а не случайными;
- нулевое улучшение не является автоматическим запретом разбиения, если
  неоднородность положительна и другие ограничения допускают рост;
- `bootstrap=false`, один элемент ансамбля, `max_features=All` дают обычное CART
  с теми же ограничениями на данных с однозначным лучшим разбиением;
- классификация проверяет усреднение вероятностей, отсутствующие классы,
  ничьи, один класс и неравные кратности;
- одинаковый seed, повторный `fit`, разные `n_jobs`, оба layout;
- один объект, один признак, константная матрица, пустой пакет запросов,
  неправильные параметры и исключение рабочей задачи.

### Необязательная сверка со sklearn — можно поручить агенту

При желании поручите ИИ-агенту подготовить несколько маленьких эталонных
примеров в Python со sklearn 1.8.0 и сохраните входы/ожидаемые ответы текстом в тестовых данных.
Python и sklearn не становятся зависимостями сборки C++.
**Эта сверка необязательна и на зачёт не влияет.** Её сценарий и код можно
поручить агенту; студент проверяет смысл сравнений.
В этой проверке разрешено использовать библиотеку как независимый эталон,
но не вызывать её вместо собственной модели.

Для точного сравнения используйте `bootstrap=False`, `n_estimators=1`,
`max_features=None`, одинаковую глубину и `min_samples_*`, простые представимые
числа и единственный лучший порог. Сравнивайте предсказания и вероятности,
а не внутреннюю нумерацию узлов. Для проверки весов отдельно сравните CART
с `DecisionTreeRegressor/Classifier.fit(..., sample_weight=counts)`.
Пример должен различать подсчёт уникальных индексов и сумму кратностей.

Лес со случайными bootstrap-выборками не сравнивается по равенству ответов
при одинаковом числовом seed Python и C++: совпадение такого seed не задаёт
общую последовательность извлечений. Для ручных тестов элементов ансамбля передавайте
одни и те же заранее подготовленные кратности.

## Самостоятельная часть и работа с агентом

Самостоятельно проектируются композиция, владение, фабрика/создание элементов ансамбля,
выборки объектов и признаков, RNG и распределение seed, агрегация и согласование
классов. Изменения алгоритма базовой модели также пишутся самостоятельно.
Сначала получите и проверьте последовательную реализацию.

Главная задача для агента — написать с использованием `std::jthread`
ограниченное распараллеливание уже
определённых независимых задач, помочь с диагностикой и проверками.
Студент заранее задаёт границы задач, владельцев данных, правило seed и порядок

Документацию, тестовую инфраструктуру и освоенные ранее настройки сборки
тоже можно делать с агентом. Предметные ожидаемые ответы и свойства тестов
проверяет студент. Эти правила действуют и для трека со звёздочкой:
алгоритм леса и проектные решения самостоятельные, явно разрешённая
инфраструктура — с агентом.

Разрешено просить объяснить средство языка; нельзя поручать готовую реализацию
изучаемого алгоритма. Граница задаётся темой работы, а не длиной функции.
Любой принятый код нужно уметь объяснить и изменить без агента.
В `docs/agent_log/lab_4.md` фиксируются значимые запросы, что принято/изменено/
отклонено, способы проверки и обнаруженные проблемы. Обновите `AGENTS.md`.

## Общие требования и сдача

- C++20, CMake, библиотека ядра отдельно от приложения, тесты в CTest,
  сборка без предупреждений при `-Wall -Wextra`.
- В Debug работают ASan/UBSan. Если среда поддерживает ThreadSanitizer,
  его можно запустить отдельно; одновременно с ASan его не подключают.
- Алгоритмы и метрики машинного обучения из сторонних библиотек не используются.
- Модели сохраняют интерфейсы `IModel`, `IRegressor`, `IClassifier` из работы 3.
  Для классификации `classes()` определяет порядок столбцов `predict_proba`.
- Ядро сообщает об ошибках исключениями и не печатает. Приложение перехватывает
  ошибку, показывает сообщение и возвращает ненулевой код.
- Проверяются пустое обучение, отсутствие признаков, несовпадение размеров,
  нечисловые/бесконечные входы и несовместимые параметры. `predict` до обучения
  запрещён. Ноль тестовых объектов возвращает пустой результат правильной формы.
- После `fit` нет ссылок на уничтоженные локальные матрицы и представления.
  Выбор layout не меняет логические ответы.
- Тесты не зависят от случайного удачного попадания: для точных ожидаемых
  ответов подавайте контролируемые элементы ансамбля/планы, а свойства RNG проверяйте
  отдельно. Тестовые вспомогательные типы не должны усложнять рабочий API.

Сдаются продолжение репозитория, актуальные README и документация интерфейсов,
`AGENTS.md`, журнал `docs/agent_log/lab_4.md`, тесты и результаты измерений.
В README опишите владение и создание элементов ансамбля, random_state, порядок
суммирования, обработку ошибок потоков и стоимость вычислений.

Зачёт требует работоспособности, самостоятельной реализации предметной части,
прохождения тестов и понимания кода. Улучшение точности или ускорение на
каждом датасете не является условием зачёта. Подбор параметров и полноценный
анализ качества остаются содержанием работы 5; её звёздочка — permutation
feature importance, реализовывать её здесь не нужно.
